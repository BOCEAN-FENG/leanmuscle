# muscle.md 的读取与保存

## 数据与技能分开

`assets/muscle-template.md` 是空白结构，不是用户档案。把真实数据放入该用户的 `muscle.md`，绝不放进技能安装目录、技能 Git 仓库或共享示例。一个档案只属于一个明确的人；代他人做计划时单独建档，不覆盖当前用户。

用户请求长期教练并建立档案即授权必要记录与后续更新，不逐次请求重复确认。用户选择不保存或只聊天时遵从该选择；对不愿保存的健康详情只记录其同意的训练限制。最少化收集，不存不必要的身份资料。

## 在 ChatGPT Work 中

1. 使用当前 Library 技能和工具，先读其说明，遵守当前接口、文件身份、下载和写回流程。不要硬编码包版本、过期命令或本技能作者的文件 ID。
2. 用户指定档案引用或已知有效 ID 时复用；否则精确搜索文件名 `muscle.md`。多份候选时仅查看足以区分所属人的元数据，必要时请用户选，不能任选最新一份或合并他人健康数据。
3. 读取当前内容后更新。只缺部分字段时补齐，不重建覆盖历史。读取失败不等于不存在；不要因工具报错创建重复档案。
4. 首次保存创建一次文件；后续替换同一个 Library 文件，保留身份及版本历史。若返回具体版本，使用版本条件；冲突时重新读取并合并本轮变更，不去掉保护强写。
5. 编辑前保留原始内容；在草稿上修改，确认已有记录、不相关字段、用户备注均保留，检查单位、时间、计划版本及新增记录；按 Library 当前要求完成写回和身份元数据处理。
6. 检查实际结果再报告完成。失败时说明未保存，保留可恢复草稿和待写变更；不声称已跨对话记住。下次尝试以当前持久版本为基础，避免重放同一条记录。
7. 成功后按环境要求提供 `muscle.md` 文件入口；不暴露内部 ID、版本锁、上传地址或把健康详情传到其他服务。除非用户要求，不新建一堆独立计划文件，计划和日志均在档案中。

## 在明确的本地持久环境中

- 用户指定路径时使用；路径未指定且本地目录已确认持久时，用 `~/.lean-muscle-coach/profiles/default/muscle.md`，首次告知位置。多用户用各自 profile 子目录，不根据真实姓名构建路径。
- 同目录临时文件写入并校验后原子替换，保留 UTF-8；更新前后对照修改时间或内容摘要，发现并发变更先重新读取合并。
- 不自动 `git add`、提交或推送健康档案。Windows 的 `~` 按当前用户主目录解析，不写到其他人的目录。
- 只有临时文件系统或没有文件工具时，明确无法保证跨会话保存；给出档案文本供用户带入下次对话。不要把沙盒路径等同于永久保存。

## 档案不变量

- 保留 `schema_version`、`profile_id`、`timezone`、`onboarding_status`、`created_at`、`updated_at`。首次真实建档时生成 ID，不用身份证或生日。
- 对个人数据标注来源、测量/报告日期及“未知/未测/不愿提供/估算”，零不是缺失值。
- 保存基线、当前状态、当前计划、每次实际训练、身体/饮食记录、复盘及计划变更。计划条目不得自动变成完成记录。
- 每条训练/打卡用稳定 ID；重试按 ID 去重。相同日期两次训练不自动认定重复，先比较或询问。
- 纠正数据注明“原值作废、修正值、原因和日期”；趋势只用有效记录。没有可靠来源就标记待确认。
- 多日数据保留逐日原始值，不能只写均值。未提供的数据不补造。
- 历史变长时先读当前计划和近期相关段落；归档须保留全部原始记录并在主档案索引，不能为省上下文静默删除历史。
- 用户要求删除或清除某段时按权限完成；说明是否仅当前可见档案变更，不声称删除无法控制的聊天或备份历史。


## 情境状态与兼容旧档案

旧schema与已有muscle.md继续有效。只在本轮实际需要时增补“当前相关状态与待办”“近期情境记录”“调整尝试与结果”等段落，保留所有原值、计划和历史，不因技能更新重建档案或自动修改个人计划。

当前状态记录有效时间、来源和待核实处；区分一次晚练与固定习惯、报告时间与事件时间、已知事实与待验证解释。问题已回答或用户不愿提供时标记，避免重复追问；状态改变时更新而非永久贴标签。

调整尝试记录触发事实、候选解释、建议、是否采纳/执行、观察指标、复查时间和回退条件。未采纳不写成已实施，症状不写成激素异常或疾病诊断。未知资料不以“没有”填充。

先满足当前辅导需要，再合并必要写回；普通知识问题、技能设计讨论、重复解释无新事实时不写健康档案。知识库和测试材料不得混入个人档案；授权更新技能不等于授权把个人健康数据放进技能Git。
